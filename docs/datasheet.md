# Datasheet: вопросы и ответы Stack Overflow по MLOps-инструментам

Датасет для дообучения модели отвечать на технические вопросы по эксплуатации
ML: трекинг экспериментов, оркестрация пайплайнов, деплой и сервинг моделей,
версионирование данных. Одна строка — один пример:
`{"id", "topic", "messages": [system, user, assistant]}`.

Числа ниже — из `metrics/*.json` и `dvc metrics diff v1 v2`; текущая версия
в `params.yaml` — `v2`.

## 1. Источник

| | |
|---|---|
| Откуда | Stack Overflow, открытый Stack Exchange API v2.3 |
| Что берём | вопросы с принятым ответом, по 57 тегам MLOps-инструментов (список в `params.yaml → fetch.tags`) |
| Тема (`topic`) | тег вопроса: `mlflow`, `dvc`, `kubeflow-pipelines`, `airflow`, `amazon-sagemaker`, `tensorboard`, `wandb` и т. д. |
| Снимок | 2026-09-20, 85 запросов к API, 2751 вопрос |
| Как воспроизвести | `make repro`: стадия `fetch` собирает снимок в `data/source/`, дальше он живёт в кэше DVC |

Собрано с нуля парсером `src/fetch.py`, готового набора здесь нет. Из каждого
тега берётся до 80 самых популярных вопросов с принятым ответом; вопрос с
несколькими тегами достаётся первому из них (редкие теги обходятся раньше
частых, иначе `airflow` забрал бы всё). Первые 40 вопросов тега — шард 0
(версия v1), следующие 40 — шард 1 (v2 = шарды 0 и 1).

`id` примера — `so_<question_id>`: по нему восстанавливается ссылка
`https://stackoverflow.com/q/<question_id>`. Авторы постов в данные не попадают.

## 2. Лицензия

Тексты вопросов и ответов распространяются под **CC BY-SA**: 4.0 для
материалов с 2018-05-02, 3.0 для более ранних. У ответов лицензию отдаёт API,
у вопросов версия определяется по дате публикации (`src/fetch.py`).

| Лицензия | Вопросов | Ответов |
|---|--:|--:|
| CC BY-SA 4.0 | 1415 | 1480 |
| CC BY-SA 3.0 | 247 | 182 |

Условия: указывать авторство (ссылка по `id`, см. выше) и распространять
производные материалы на тех же условиях. Датасет — производная работа,
поэтому и он должен раздаваться под CC BY-SA. Для учебной работы этого
достаточно; для коммерческого обучения нужна отдельная юридическая проверка.

## 3. Что сделано руками

Снимок API не сдаётся как есть. Стадии `collect` и `clean` делают следующее,
и каждое действие видно числом в метриках (v1 → v2):

| Действие | Где | v1 | v2 |
|---|---|--:|--:|
| Просмотрено строк снимка | `collect.json → rows_scanned` | 1660 | 2751 |
| Сверка с разметкой источника: ответ принят и относится к этому вопросу | `dropped_answer_mismatch` | 0 | 0 |
| Отброшено по голосам (вопрос или ответ < 1) | `dropped_score` | 363 | 827 |
| Отброшены ответы длиннее 3000 символов (логи, дампы) | `dropped_answer_length` | 65 | 97 |
| Системная реплика: в источнике её нет, добавлено 5 русских вариантов | `system_prompt_variants` | 5 | 5 |
| Фильтр длин вопроса (30–4000 символов) | `clean.json → dropped_length` | 104 | 165 |
| Маскирование ПДн (почты, телефоны, даты рождения) | `pii_hits` | 39 почт | 62 почты |
| Точные дубли / near-dup | `dropped_exact_dup` / `dropped_near_dup` | 0 / 0 | 0 / 0 |

Из 1660 (2751) строк снимка в датасет доходит 1128 (1662), то есть 68 % (60 %).
Нули в дедупликации — не «проверки нет»: точная и near-dup стадии работают
(`tests/check_data.sh`, пункт 2, подкладывает точный дубль и почти-дубль и
получает по единице), а в этом источнике повторов и правда нет — вопросы
уже уникальны по `question_id`. Near-dup с порогом 0.85 нашёл 0; при пороге 0.5
на v2 — тоже 0.

Системная реплика составлена мной и в источнике отсутствует. Вариант выбирается
детерминированно по `sha1(id)`, поэтому `raw.jsonl` воспроизводим.

Пример строки (ответ сокращён):

```json
{"id": "so_60098624", "topic": "ray", "messages": [
  {"role": "system", "content": "Ты инженер по MLOps и отвечаешь на технические вопросы со Stack Overflow. ..."},
  {"role": "user", "content": "Тема:\nray\n\nВопрос:\nWhat is ray::IDLE and why are some of the workers running out of memory?\n\nI'm running ray on EC2. ..."},
  {"role": "assistant", "content": "ray:IDLE are idle processes that are staying in the processing pool. ..."}]}
```

## 6. Разнообразие и пороги

Пороги `diversity` из `params.yaml` не менялись — ни один не снижен.

| Порог | Значение | v1 | v2 |
|---|--:|--:|--:|
| `min_examples` | ≥ 1000 | 1128 | 1662 |
| `min_system_prompts` | ≥ 3 | 5 | 5 |
| `min_groups` | ≥ 50 | 54 | 54 |
| `max_group_share` | ≤ 10 % | 3.4 % | 4.5 % |
| `min_answer_len_ratio` (p90/p10) | ≥ 1.6 | 8.03 | 8.2 |
| `max_same_length_share` | ≤ 25 % | 0.4 % | 0.5 % |
| `max_duplicate_answer_share` | ≤ 30 % | 0 % | 0 % |

Запас по числу групп мал: 54 против 50. Тег с единственным примером
(`mleap`, `horovod`, `deepspeed`) считается группой, но обучающей ценности
почти не несёт — при сужении набора порог `min_groups` упрётся первым.

## 7. Как устроен сплит

Разбиение 80 / 10 / 10 идёт **по группам**: группа — нормализованный тег
(`split.group_key: topic`), целиком уходящий в один из сплитов. Группы
перемешиваются с `seed: 42`, затем крупные раздаются первыми — каждая тому
сплиту, которому больше всего не хватает до целевой доли. Доли получаются
80.0 / 10.0 / 10.0 %.

Проверка контаминации — отдельная стадия (`make contamination`) с тем же порогом
Жаккара, что и в `clean` (0.85): пересечения train/test по id, по тексту, по
группам и near-dup пары. На v1 и v2 — по нулям. Стадия `split` при любом
ненулевом пересечении падает.

Следствие группового сплита: **тестовые теги модель во время обучения не
видит**. В v2 в тесте `amazon-sagemaker-studio`, `feature-store`,
`great-expectations`, `knative`, `ludwig`, `mleap`, `mlops`, `netflix-metaflow`,
`openvino`, `ray-tune`, `tensorboardx`, `triton`. Тест измеряет перенос на
незнакомый инструмент, а не знание уже виденных.

## 8. Чего датасет не покрывает

- **Язык.** Вопросы и ответы английские, русские только системные промпты. Для
  русскоязычного ассистента набор годится как техническая база, но не как
  образец языка.
- **Только принятые ответы.** Вопросы без принятого ответа отсутствуют, а их
  много: у `mlflow` принят ответ примерно на каждый третий вопрос. Набор
  смещён в сторону вопросов, которые удалось решить.
- **Популярное и старое.** Из тега берутся самые высокорейтинговые вопросы, то
  есть в основном старые: 15 % вопросов — CC BY-SA 3.0, до 2018 года. Версии
  инструментов в них устарели, ответы про `airflow 1.x` или `tensorflow 1.x`
  сегодня могут вести не туда. Даты и версии в примерах не проверялись.
- **Короткое и среднее.** Вопросы длиннее 4000 символов и ответы длиннее 3000
  отброшены — вместе с ними ушли длинные трассировки и большие конфиги.
- **Правильность.** «Принят автором» и «получил голоса» — не «верен». Запуск
  кода из ответов не проверялся.
- **Перекос по тегам.** В v2 у 31 тега ≥ 20 примеров, у 17 тегов < 10. Метрики
  по редким тегам (`mleap`, `ludwig`, `horovod` — 1–2 примера в v2) шумны, а
  `mleap` и `ludwig` как раз в тесте.
- **ПДн.** Маскируются почты, телефоны и даты рождения при маркере рождения.
  Регулярка почты срабатывает и на URL вида `abfss://container@account.dfs...`
  и на поле `"email"` в примерах JSON: их `[EMAIL]` — ложные срабатывания на
  коде, зато утечки адресов такой фильтр не пропускает. Имена и никнеймы в
  тексте ответов не маскируются: они публичны в источнике.
- **Остаток разметки.** HTML-сущности раскрыты, служебные комментарии
  редактора убраны. В одной строке остаётся `&amp;` — внутри процитированного
  HTML: это содержимое самого поста, а не артефакт разбора.
