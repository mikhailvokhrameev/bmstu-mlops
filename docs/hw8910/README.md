# ДЗ 8: выпуск синтетического стенда

Исходный неисправленный прототип сохранён в коммите `3099a59`. Стенд использует только синтетические данные: его успешный выпуск не доказывает качество реальной модели. Результаты опытов и таблица исправлений — в `EXPERIMENTS.md` и корневом `defects.csv`.

Нужен Python 3.12. Для Prefect установите `python -m pip install -r requirements-hw8910.txt`. Запуск из корня проекта:

```sh
python lab.py --workspace /tmp/mlops-hw8910 init
python prefect_flow.py --workspace /tmp/mlops-hw8910 --fail-after-prepare
python prefect_flow.py --workspace /tmp/mlops-hw8910
python service.py --workspace /tmp/mlops-hw8910 --port 8091 --warmup-seconds 10
make check-hw8910 PYTHON=python
```

Первый запуск flow намеренно завершается ошибкой после подготовки; второй использует устойчивый кеш. `lab.py` сохраняет исходные команды `init` и `run`. Ключ кеша зависит от содержимого и конфигурации; журнал попыток отделён от событий выпуска. Запись указателя и журнала атомарна при одном писателе, а незавершённая публикация восстанавливается при следующем запуске. Проверки без Prefect и модели находятся в `tests_hw8910/test_release.py` и `test_incidents.py`; `test_flow.py` дополнительно запускает настоящий Prefect и использует локальный сервер. Исходный журнал падения — `evidence/incidents-before.log`, успешный журнал — `evidence/incidents-after.log`.

HTTP-сервис здесь — учебный STUB, загружающий версию только при запуске; настоящий FastAPI и модель относятся к ДЗ 10. Не добавляйте рабочий каталог, кеши, веса и секреты в Git.

Четыре задачи Prefect передают небольшие описания подготовки и выпуска. У задач
отключён автоматический кеш Prefect: кеширование по пути workspace скрыло бы
изменение файла на том же пути. Подготовка использует собственный устойчивый
content-addressed кеш в `workspace/cache`, запись выполняется атомарно. Допуск
и публикация исполняются при каждой попытке; их нельзя пропустить кешированным
статусом задачи. `attempt_id` уникален для запуска, ключ подготовки зависит от
данных и всей конфигурации, `release_id` — от manifest и отчёта оценки.

Полный зелёный журнал (контракты, семь сценариев и настоящий Prefect):
`evidence/hw8-all-green.log`. Расширенный тест Prefect проверяет сбой и восстановление
в другом процессе, изменение данных и каждого из четырёх параметров подготовки,
неполный/чужой/отклонённый отчёт, уникальность попыток и отсутствие дубликатов выпуска.
Нужны локальные сокеты для HTTP и временного сервера Prefect; сетевой доступ к
внешним сервисам не нужен. Для воспроизведения в подготовленном окружении:

```sh
PYTHONPATH=/private/tmp/bmstu-prefect /opt/anaconda3/bin/python3.12 -m unittest discover -s tests_hw8910 -v
```
